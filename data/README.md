# Data

Raw data is **not** included in this repository (DeepLense Model II is ~1.3 GB;
the turbulence D2 snapshot archive is ~4.1 GB). This file explains what each
experiment needs, where to get it, and which script turns the raw file into
the small cache the training/evaluation code actually reads.

## 1. DeepLense Model II (strong gravitational lensing, 3-class substructure)

- **Source**: the ML4SCI DeepLense project. The `model_II.npz` file (64x64
  simulated lens images, classes `axion` / `cdm` / `no_sub`) is generated by
  the pipeline described in Alexander et al. 2020, *Deep Learning the
  Morphology of Dark Matter Substructure*, ApJ 893:15 (arXiv:1909.07346).
  Obtain it from the ML4SCI DeepLense project page/repository
  (https://github.com/ML4SCI/DeepLense) or from whoever maintains your local
  copy of the DeepLense Model II release; this repository does not redistribute
  the file.
- **Expected format**: a single `.npz` with per-class `train_x` / `val_x`
  arrays of 64x64 float images.
- **Cache-building entry point**: `code/data_lens.py` (pilot / round-1/2
  experiments) and `code/data_lens_r3.py` (round 3 / 3b, the arms used in the
  paper's main results). Both read the raw `.npz` path from:
  - env var `LENS_NPZ` (falls back to the hardcoded constant `NPZ_DEFAULT` at
    the top of each file, a private path on the original authors' cluster —
    **edit this constant or set `LENS_NPZ` to your own path**),
  - and write their per-class cache under env var `LENS_CACHE_DIR` (falls back
    to the hardcoded constant `CACHE_DIR_DEFAULT`, likewise a private path —
    **edit or set `LENS_CACHE_DIR`**).
  The cache is built automatically on first call (~15 MB, 100 train + 200
  held-out images per class); nothing needs to be run manually beyond pointing
  the two paths/env vars at your own filesystem.

## 2. Turbulence D2 (Khojasteh et al. 2022, 2D velocity snapshots)

- **Source**: Khojasteh et al. 2022, DOI `10.15454/GLNRHK`. The file used is
  `2D_velocity_snapshot_sub_domain_2.zip` (sub-domain 2, 1000 snapshots,
  ~4.1 GB) from that dataset's data repository.
- **Cache-building entry point**: `code/preprocess_d2.py` stream-parses the
  zip (never loads the full array into RAM) into a compact per-timestep cache
  read by `code/data_d2.py`.
  - Raw zip path: `--zip` argument, defaults to the hardcoded constant
    `ZIP_PATH_DEFAULT` in `code/preprocess_d2.py` (a private path on the
    original authors' cluster) — **edit this constant or pass `--zip
    /your/path/2D_velocity_snapshot_sub_domain_2.zip`**.
  - Cache directory: `--out`/positional argument in `preprocess_d2.py`,
    defaults to the hardcoded constant `CACHE_DIR_DEFAULT` in both
    `preprocess_d2.py` and `data_d2.py` (again a private path) — edit both
    constants (or pass the directory explicitly) if you relocate the cache.
  - Run once: `python3 code/preprocess_d2.py --zip /your/path/2D_velocity_snapshot_sub_domain_2.zip /your/cache/dir`.
    After that, `data_d2.py` reads the cache via memmap.

## Why nothing is bundled here

Both datasets are large, third-party, and (for DeepLense) not something we are
positioned to redistribute; the turbulence archive is 4.1 GB and clearly out
of scope for a code-release repository. `results/` in this repository instead
ships the *outputs* of running these pipelines (jsonl metric logs, `meta.json`
per generative arm, and a 20-sample subset of generated images per arm) so
the paper's numbers and figures can be checked without re-downloading or
re-running anything — see the top-level `README.md` for the full
reproduction path if you do want to regenerate from scratch.
